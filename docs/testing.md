# 测试与 TDD

本文档定义 Go 实现的测试流程和完成标准。

## 工作流程

每个行为变更遵循 Red → Green → Refactor：

1. 在功能文档中新增或修改验收条件；
2. 编写能够证明该条件尚未满足的失败测试；
3. 实现使测试通过的最小代码；
4. 在全部测试保持通过的前提下重构；
5. 运行对应平台测试和 CLI 冒烟测试。

验收条件使用稳定编号，例如 `HEX-001`。测试名称或注释应引用编号，保证规范与
测试可追踪。

## 测试分层

- 单元测试：与源码相邻，使用表驱动测试覆盖解析、格式化和路径计算。
- 命令测试：在进程内执行 CLI，验证每一级 `--help`、参数、stdout、stderr 和退出码；
  帮助测试还需证明不会初始化功能状态或执行外部操作。
- Golden 测试：验证表格、帮助和稳定文本格式；JSON 优先按结构比较。
- 集成测试：验证 Git、SSH/SFTP、注册表和 Shell 配置等系统边界。
- 发布冒烟测试：在干净环境执行 README 对外公布的一键安装命令，再运行
  `--version`、`--help` 和只读命令；同时验证 manifest 版本不一致、目标资产缺失
  及校验和错误时安装必定失败。
- 生命周期测试：从上一稳定版升级到待发布版本，验证失败回滚，并分别验证保留数据
  卸载和 `--purge` 卸载。

## 可测试性边界

文件系统、时间、环境变量、外部进程、Git、SSH/SFTP 和 Windows 注册表必须通过
小接口注入。接口由使用方包定义，测试采用 fake 实现；禁止依赖真实用户目录或
修改开发机配置。

测试数据统一放在 `testdata/`，临时输出使用 `t.TempDir()`。涉及文件替换的测试
必须覆盖成功、权限失败、中途失败和恢复路径。

## 平台矩阵

GitHub Actions 至少运行：

| 系统 | 测试范围 |
| --- | --- |
| Linux amd64 | 全部跨平台单元、命令和集成测试 |
| Windows amd64 | 跨平台测试及 MobaXterm、注册表、PowerShell 测试 |

平台专属测试使用 build tags 或平台文件名隔离。依赖 MobaXterm 实际安装或远端
SSH 服务的测试标记为手动/受控集成测试，不进入普通开发机默认测试集。

## 完成标准

一个功能只有在以下条件全部满足时才算完成：

- 功能文档和 CLI 文档已同步；
- 所有验收条件都有自动化测试，或明确记录无法自动化的原因；
- Linux/Windows 适用测试通过；
- 不访问真实用户配置，不泄露敏感信息；
- 写入操作覆盖 dry-run、备份和失败恢复；
- `go test ./...`、格式化和静态检查通过。
